# Graveblood — редакторы

Браузерный редактор с вкладками: **Диалоги** (`project/src/dialogues.cpp` / `dialogues.h`),
**Портреты**, **Подмена тайлов** (`project/src/supertiles.cpp`), **Группы** (`project/src/groups.h/.cpp`) и **NPC** (пока заглушка —
следующий редактор: взаимодействия с NPC). Последняя открытая вкладка запоминается.
Нужен только Python 3 (стандартная библиотека, ничего ставить не надо).

```bash
cd /cfa_engine/editors/dialogue_editor
./run.sh                      # = python3 server.py, откроет http://127.0.0.1:8765
python3 server.py --no-browser --port 9000
python3 server.py --project /cfa_engine/project --gfx /cfa_engine/project/gfx
```

По умолчанию проект ищется как `<папка редактора>/../../project`.

## Что куда пишется

| Что | Куда |
|---|---|
| Диалоги | `project/src/dialogues.cpp` + размеры массивов / `extern` в `dialogues.h` |
| Бэкап перед каждым сохранением | `editors/dialogue_editor/backups/` (последние 40) |
| Статусы ОК / В работе, NPC диалога, названия эмоций | `editors/dialogue_editor/editor_meta.json` (в игру не попадает) |

Переписываются **только изменённые** массивы `dMMM_NNN[]`, массивы миссий `dMMM[]`, `dPointers[]`
и соответствующие `extern` в .h. Всё остальное (Interact, ReactTalk, комментарии между массивами)
остаётся байт-в-байт. Внутри изменённого массива нетронутые фразы тоже сохраняются как были,
включая комментарии. Кодировка и CRLF сохраняются.

Если файл поменяли на диске после загрузки (git pull, правка руками) — сохранение предупредит.

## Ссылки на фразы

Все поля «куда перейти» хранятся как ссылка на саму фразу, а не на номер, поэтому при
вставке / удалении / переносе фраз номера пересчитываются автоматически.

Правило движка, которое учитывает редактор:

* `-1, -21, -22, -19, -28, -35, -37` — движок делает `phrase = X`, потом `phrase++`,
  т.е. реальная цель = **X + 1**. В редакторе вы выбираете саму фразу-цель.
* `-18` (выбор) — переход ровно на **X**.
* `-1` со значением `-1` показывается как «⟲ с начала».
* `-6` берёт переход из таблицы `commonConditions` — его редактор не трогает.

При удалении фразы, на которую кто-то ссылается, ссылки перенаправляются на соседнюю.

## Портреты

Сервер ищет `charNN.til.inc` / `charNN.pal.inc` по всей папке проекта (или в `--gfx`)
и собирает портрет так же, как `makePrtrt()` + `PlayerDrawing::drawChar()`
(блок 96 тайлов на эмоцию, 8bpp, 2D-раскладка 16 тайлов в ряд, 72×80 px).
`who`: `0` — Вика (char00), `-1` — NPC диалога (выберите в шапке, либо угадывается по имени),
`>0` — charID. Номера и имена персонажей берутся из `persons.cpp` (`dataPointers`).

Названия эмоций 0–6 — по нарисованным лицам: 0 воодушевлённо, 1 нейтрально / лёгкая улыбка, 2 говорит / указывает, 3 смущение / стыд, 4 влюблённость, 5 meh / не очень, 6 злость. Дальше — догадки по существующим репликам. У Вики эмоции 7+ пока не дорисованы. Переименовать можно в ⚙ (хранится в `editor_meta.json` и перекрывает эти названия).

## Превью бабла

Каждая реплика, подсказка, авто-реплика и выбор рисуются как на экране GBA (240×160):
шрифт берётся из `src/sys8.font.h`, перенос слов — точная копия `BubbleGum::writeStrA()`,
размеры и позиции баблов — из `PlayerDialogue::showDialog()/showChoice()`, портрет — в точке 168,72.
Текст пишется в UTF-8 байтах, как его получит GBA.

Под превью — «строк N/M». Если текст не влезает, лишние строки рисуются красным под баблом
и появляется ошибка в проверках. В выборе клик по превью перебирает подсветку вариантов.
Цвета (палитра уровня неизвестна редактору) и масштаб — в ⚙. Рамка условная: настоящие
тайлы рамки лежат в тайлсете уровня.

## Горячие клавиши

`Ctrl+S` сохранить · `Ctrl+B` панель · `Ctrl+F` поиск · `Ctrl+Z / Ctrl+Shift+Z` отмена/повтор
(вне текстовых полей) · `Alt+↑/↓` соседний диалог · `Esc` закрыть окно.

## Проверки

* длина строк (`name[27]`, `text[108]`, `answerN[33]`) — иначе не скомпилируется;
* не-ASCII символы (шрифт GBA);
* ссылки за пределы диалога;
* текст, который не влезает в бабл (по настоящему шрифту);
* диалог, который кончается репликой (движок прочитает за концом массива);
* выбор длиннее `buf[85]` в `showChoice()`; опционально — `buf1[12]` (см. ⚙).

## Удаление

Удалить можно только **последний** диалог миссии: номер диалога = индекс в `dMMM[]`,
и его использует код игры (NPC, specialDIAL, двери). Новые диалоги и миссии добавляются в конец.

## Порядок миссий (missionOrder)

Если в проекте есть `src/mission_order.cpp` с массивом `missionOrder[]`, дерево
слева показывает миссии **в порядке прохождения**, а не по номеру `dNNN`.
Перед ID стоит позиция в сюжете (`10. d020 …`); миссии, которых нет в
`missionOrder`, идут в конце со знаком `?`. Переход «следующий/предыдущий
диалог» тоже идёт в этом порядке.

Номер `dNNN` — это ID миссии (`curMission`, индекс в `dPointers`), он никогда
не меняется: редактор сохраняет `dPointers` по ID, как и раньше. Новая миссия
(«+ миссия») получает следующий свободный ID; чтобы поставить её в нужное место
сюжета, впиши этот ID в `missionOrder[]`. Файл `mission_order.cpp` редактор только
читает.

## Вкладка «Подмена тайлов»

Таблица `superTilerPairs[]` из `project/src/supertiles.cpp` — то, что fgtile подменяет на лету
(`GameState::setSuperTile`). Строка таблицы = пара состояний одного места (`a` — игрок
слева/сверху, `b` — справа/снизу); число из tmx (`treetype` у триггера, `switch2dial` /
`switchTile` у двери) — номер состояния, он же номер слева в списке.

* **Список слева** — пары с номерами; комментарии `portTo = N` из `supertiles.cpp` показаны
  плашками «N · map-…», под каждой парой — плашки «уровень · карта», где она используется
  (🚪 — подмена при входе через дверь, карта назначения). Данные — из
  `project/tools/supertile_usage.py --json`. Поиск — по номеру, названию или карте.
* **Сжатый тайлсет** — картинка `images/mts-*.bmp`, пересжатая так же, как `tmx2incl bc[u]`
  (повторы и отражённые тайлы выкинуты, флаг `u` учитывается; проверено байт-в-байт). Именно
  в этой нумерации считает `setSuperTile`. Зелёным — «откуда», красным — «куда» (эти тайлы VRAM
  заменятся), пунктиром — второе состояние пары; обводится область целиком, без сетки. Сначала
  идут тайлы VRAM фона (0–863, `applyTileSet`), затем полоса **ROM** и остальные тайлы с новой
  строки: их можно брать, но не заменять. Слева — номер первого тайла в строке.
* **Выделение мышью**: режим «откуда» или «куда», протянуть по тайлам — задаст начало и
  «сколько», клик — только сдвинет начало. Или вписать числа руками.
* **Карта** — справа от тайлсета, превью tmx с подменой: «без подмены» / как в `a` / как в `b`.
  Колёсико — масштаб к курсору, средняя (или левая) кнопка — двигать, «⤢ целиком» — вся карта,
  «→ к изменениям» — приблизить к местам, нарисованным тайлами из «куда» (обведены жёлтым).
* **fgtile на карте** (галочка «fgtile», «все» — ещё и двери/телепорты без подмены): триггеры
  подмены — прямоугольники своего размера (клетка `x/8, y/8`, `route`×`num` клеток, как `hitBoxx`),
  пунктир делит стороны a/b; двери со `switch2dial`/`switchTile` — оранжевые 🚪. Триггеры выбранной
  пары подсвечены голубым. Клик по fgtile выбирает его пару в списке; клик по паре в списке
  приближает карту к её fgtile («→ к fgtile» — то же вручную).
* **Правка fgtile**: тащить — двигать (по клеткам 8 px), белый уголок — размер, строка над картой —
  `treetype`, `turn`, `route`, `num`, `x`, `y` (у двери — `switch2dial`/`switchTile`); стрелки —
  сдвиг на клетку, Del — удалить. «+ fgtile» — новый триггер выбранной пары в центр видимой части
  карты, «+ пара с fgtile» — новая пара в конец таблицы и триггер для неё.
* **Сохранить** пишет всё сразу: `supertiles.cpp` и изменённые карты. В tmx меняются только
  тронутые объекты (остальное байт-в-байт, новым — следующий `nextobjectid`), бэкап карт — в
  `backups/`. После правки карт пересоберите графику (`build_graphics.sh`). Если карту поменяли
  в Tiled после загрузки — сохранение предупредит.
* Тайлсет и карта по умолчанию — из `build_graphics.sh` (первый `bct` для этой карты) и списка
  «где используется»; если карта использует второй тайлсет (`tileSets[1]` и т.п.) — выберите вручную.

В редакторе всё в **тайлах**; в `supertiles.cpp` «куда/откуда» записаны ×2 (полутайлы) —
пересчёт делает сервер. При сохранении переписываются только изменённые строки (выражения
вроде `2630+270+4` остаются, если число не менялось), новые пары — в конец, затем
`supertile_usage.py --write` обновляет `@ …` в комментариях. Бэкап — `backups/supertiles_*.cpp`.
`Ctrl+S` — сохранить, `Alt+↑/↓` — соседняя пара.

## Вкладка «Группы»

Группы персонажей (скейтеры, тихие, модные…) — `project/src/groups.h` + `groups.cpp`. Оба файла
**генерирует редактор** целиком (бэкап — `backups/<время>_groups.*`); руками править можно, но в том
же формате строк. Три подвкладки:

* **Группы и отношения** — карточки групп (название, ключ `G_…` для кода, описание), граф и
  матрица отношений −2…+2 (симметрично). На графе: клик по группе, потом по другой — следующее
  значение по кругу; два клика по одной — отношение внутри группы; клик по линии — тоже по кругу.
  −2 — двоих из этих групп нельзя позвать вместе (`Companions`). `NONE` («без группы») ладит со всеми.
* **Состав** — колонки групп, персонажей перетаскивают мышью. Один персонаж — одна группа.
* **Фразы** — свои ответы группы: ситуация (сейчас TALK → SUBJECT и TALK → CRITICIZE) × тема ×
  отношение персонажа к теме (0, 1, 3, 4). Пустая клетка — игра скажет общую фразу из
  `dialogues.cpp` (видна под «общие»). Проверки: ≤ 107 символов, только ASCII (шрифт GBA).

Новая ситуация — добавить в `SITUATIONS` (`grcore.py`), пересохранить группы и вызвать
`Groups::phrase()` в нужном месте игры. `Ctrl+S` — сохранить.
