# gbadbg — отладчик Graveblood на ядре mGBA

Свой фронтенд к libmgba (mGBA 0.10.5) на SDL2 + Dear ImGui: одно окно с панелями,
перемотка по кадрам, просмотр тайлов/спрайтов/палитр, изменения памяти за кадр, лог ошибок ядра.

## Сборка (CachyOS)

```fish
sudo pacman -S --needed cmake git gcc sdl2-compat mesa
cd cfa-engine/tools/gbadbg
cmake -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j(nproc)
```

При первой конфигурации CMake сам скачает mGBA 0.10.5 и Dear ImGui (нужен интернет),
дальше пересборка — только `cmake --build build -j(nproc)`.

## Запуск

```fish
./build/gbadbg ~/graveblood/graveblood.gba
# опции: --elf out/graveblood.elf --src-root ~/graveblood --binutils <префикс>
#        --save путь.sav (по умолчанию рядом с ромом: graveblood.sav)
#        --history-mb 1024 (сколько ОЗУ под перемотку)
```

Сохранение загружается **копией в память** — отладчик никогда не перезаписывает `.sav` на диске.
Раскладка панелей запоминается в `~/.config/gbadbg/layout.ini` (удали файл — вернётся раскладка по умолчанию).

## Управление

| Клавиши | Что делают |
|---|---|
| стрелки, X / Z, A / S, Enter, Backspace | GBA: крестовина, A / B, L / R, Start, Select (как в mGBA) |
| Space | пауза / продолжить |
| `,` / `.` | кадр назад / вперёд (с Shift — по 10) |
| Tab (держать) | ускорение |
| M | пометить показанный кадр как «плохой» (с заметкой из поля в Timeline) |

## Панели

- **Game** — экран ×3. «sprite boxes» — рамки всех спрайтов; наведение на строку в Sprites подсвечивает спрайт красным.
- **Tiles** — VRAM ×2. По умолчанию OBJ 8bpp по 16 тайлов в ряд — как `mss-01.bmp`, персонажи собраны целиком.
  Можно BG (весь или по charblock), 4bpp + банк палитры, тайлов в ряд, масштаб, сетка.
  Красные рамки — тайлы, записанные **за последний кадр** (видно, кто кому затёр графику).
  Подсказка на тайле: адрес, номер тайла в разделе, номер для OAM (в единицах по 32 байта) или для BG.
- **Sprites** — все 128 записей OAM: картинка, позиция, размер, тайл, палитра, приоритет, флаги; режим 1D/2D.
- **Palette** — BG и OBJ палитры, по наведению индекс и BGR555.
- **Timeline** — полоса истории: красные риски — кадры с ошибками ядра, оранжевые — помеченные плохие,
  белая — текущий кадр. Клик/перетаскивание — перемотка. Списки «плохих» кадров и кадров с ошибками.
  «pause on error» — эмуляция сама встаёт на паузу на кадре, где ядро увидело ошибку
  (чтение по плохому адресу, прыжок в никуда и т.п.).
- **Log** — сообщения ядра и отладочный вывод игры (регистры mGBA `0x04FFF600`), с номером кадра;
  клик по строке — перейти к этому кадру.
- **Frame diff** — что изменилось в EWRAM/IWRAM/Palette/VRAM/OAM за показанный кадр: число байт и диапазоны;
  клик по диапазону — открыть его в Memory, наведение — «было → стало».
- **Memory** — hex-просмотр регионов, байты, изменённые за кадр, подсвечены красным.

## Как устроена перемотка

На каждый кадр сохраняется состояние ядра **до** кадра и нажатые кнопки. Хранится не всё
состояние (~400 КБ), а XOR с предыдущим кадром, ужатый по нулям — обычно единицы КБ на кадр;
каждые 60 кадров — ключевой кадр. Показ кадра N = загрузить состояние до N, нажать те же кнопки,
выполнить кадр: эмуляция детерминирована, картинка и память получаются ровно такими же.
Когда история упирается в лимит `--history-mb`, старые кадры выбрасываются.

«Resume» с прошлого кадра продолжает игру **оттуда**: записанное «будущее» после него стирается
(вместе с логом, ошибками и пометками после этого кадра).

## Трассировка и исходники (этап 2)

Нужен `out/graveblood.elf` с отладочной информацией — в Makefile игры `-g` (уже включено; на `.gba` не влияет).
gbadbg сам находит `out/<имя рома>.elf`, имена и строки читает через `arm-none-eabi-nm`/`objdump`
из `$DEVKITARM/bin` (или `--binutils /путь/arm-none-eabi-`). Исходники ищутся от корня игры
(папка над `out/`, или `--src-root`).

Как это работает: кадр выполняется по одной инструкции (тот же порядок, что у обычного кадра, поэтому
состояние совпадает), переходы PC сверяются с адресами функций из `.elf` — получаются вызовы и возвраты.

- **Trace** — для показанного кадра (на паузе трассируется автоматически):
  - *Events* — ошибки ядра с **полным стеком вызовов** в момент ошибки и результаты «Who wrote»;
  - *Call tree* — дерево вызовов с числом вызовов и долей кадра (включительно / сама функция);
  - *Profile* — функции по тактам (где тратится кадр);
  - *End stack* — где был процессор в конце кадра.
  Клик по функции или строке стека — открыть место в **Source**.
- **Who wrote** — в Memory (адрес + сколько байт; ПКМ по байту подставляет адрес) или в Frame diff
  (выбрать диапазон → кнопка): кадр прогоняется заново, и каждая запись в эти байты попадает в Events
  со стеком вызовов (или с пометкой DMA/прерывание).
- **Source** — исходник с подсветкой строки, поиск функции по имени.
- **Activity** + `live trace` — трассировка каждого кадра прямо во время игры. В ленту попадает функция,
  которую начали вызывать после N «тихих» кадров: нажал A у персонажа — видишь `startInteraction`,
  `drawInteract` и т.д.; с `follow live` Source сразу показывает код. Двойной клик — перейти к кадру.
  Живая трассировка медленнее обычной эмуляции; если игра не успевает 60 кадров/с — выключай её и
  пользуйся трассировкой на паузе.
- В **Frame diff** и **Memory** у адресов EWRAM/IWRAM — имена глобальных переменных (`relationLVLS+0x10`).
